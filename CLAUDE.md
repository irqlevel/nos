# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository. It holds what every change has to know: the goal, the rules, how to build, and which gate to run. Reference material lives in `docs/` and is linked from where it is needed -- read the page before the work it covers.

`nos` is a hobby x86-64 / arm64 OS kernel written in C++20, Rust, and assembly. It is freestanding (no libc, no STL, no C++ exceptions/RTTI) and boots via Multiboot2/GRUB on x86-64 and the Linux `Image` protocol on arm64. It targets QEMU/KVM, KVM-based clouds (Google Cloud, Yandex Cloud), and QEMU `virt` + HVF on Apple Silicon, and boots on three real machines — a Dell Latitude 5480 (Skylake-U, UEFI, no serial port, no PS/2), where the framebuffer console and the xHCI USB keyboard are the only console channels, and two Hetzner dedicated servers, an Intel EX44 (RTL8125) and an AMD Ryzen AX41 (Intel I210), whose only console is the network. The long-term goal is a bare-metal cloud node running Linux guests under a Rust hypervisor (`plans/README.md`: stages 0–5, currently at the start of stage 3 -- `docs/hypervisor.md`).

## The goal: a kernel that is safe by design and by code

This is being built to be as safe as a kernel can be made: **no undefined behaviour, no memory corruption, no data races, no deadlocks, no resource leaks on error paths, no failure that passes in silence.** Not as a property to test for afterwards -- as the thing every design and every line is chosen for. It ranks above speed, above brevity and above getting a feature in sooner, and the long-term goal (other people's Linux guests on this machine) is why.

- **By design first.** Between two designs, take the one where the bug cannot be written over the one where a comment asks nobody to write it: a lock that owns what it guards, a handle that is looked up and not dereferenced, a ring lent under the lock that orders it, an image that is W^X. When something needs a rule to be used correctly, look for the type that makes the rule unnecessary -- the ones this tree has are listed in the Rust section.
- **By code.** The Conventions below are this, spelled out: Rust first and with as little `unsafe` as the job allows, C++ reviewed for undefined behaviour, every return value checked, every error path releasing what it took, nothing allocating or sleeping where a lock or an interrupt context forbids it.
- **A failure must be loud.** What cannot be ruled out is caught where it happens and reported, not left to surface as a wedge somewhere else: `BUG_ON` and `PANIC` on a broken invariant, the TLB shootdown that names the CPUs that never answered instead of hanging the machine, a join (`Task::wait`) still waiting after ten seconds reporting what it waits for and where that task is, the watchdogs, netconsole carrying a panic's backtrace off a box with no other console. A hang with no report is the worst outcome there is, and a change that turns one into a report is worth making.
- **A bug is a question about the design.** Fixing the instance is half of it; the other half is closing what made it possible, so that the next one of its kind does not compile, does not link, or fails a gate. The gates exist for the failures that look like success: write one when you meet another.
- **Neither speed nor safety is a guess.** A fast path may be structured differently to stay safe -- per-CPU state, a recycled pool, a lock-free ring -- but it does not drop a check or reach for `unsafe` on a hunch: measure, and say what was measured. "No behaviour change" is likewise something to show -- compare the binaries, run the gates -- not something to assert.

## Build, run, test

On macOS / Apple Silicon you almost always build inside Docker, which packages the whole toolchain (clang, nasm, grub-mkrescue, cppcheck, and the pinned nightly Rust):

```sh
./scripts/build-iso-docker.sh   # produces nos.iso + bin/kernel64.elf (GDB symbols)
./scripts/build-disk.sh         # produces nos.qcow2 (MBR disk image)
```

Native (Linux with the toolchain installed), or inside the container:

```sh
make            # = `make check` (cppcheck static analysis) + build nos.iso
make nocheck    # skip cppcheck, just build
make check      # cppcheck; check-crates.py's rules for where a crate goes; check-links.py: every link of the site and the docs into the tree names something there (fails on any finding, exit code 22)
make rust       # build only the Rust staticlib (src/crates → libkernel.a)
make smoke      # boot smoke test: build in Docker + headless QEMU, assert serial markers
make clean
make nocheck ARCH=aarch64   # arm64 -> kernel-arm64.elf + nos-arm64.img
make nocheck UBSAN=1        # the C++ under clang's UB sanitizer, either ARCH: the first report is a panic
make nocheck RUSTUB=1       # the Rust half under core's own checks of its unsafe preconditions, and overflow
```

The build is parameterized by `ARCH` (default `x86_64`; `aarch64` selects the arm64 toolchain, linker script and Rust target), and objects live in `out/$(ARCH)/`. What the Makefile will not tell you (`docs/build.md` has each at length):

- **Both architectures must stay green.** CI (`.github/workflows/ci.yml`) runs `make check` plus a build *and* a boot smoke test for `x86_64` and `aarch64`. A change to common code that only builds on x86 is a broken change.
- **Source lists are explicit, not globbed.** The Makefile has two hand-written lists, `CXX_SRC_x86_64` and `CXX_SRC_aarch64` (plus `ASM_SRC_*` for NASM and `ASM_S_SRC_*` for GNU-as). A new `.cpp` that is not added to the right list is silently not compiled; portable code must be added to **both**. Common driver code that references x86-only entry points gets an unreachable link stub in `src/base/arch/arm64/x86_driver_stubs.cpp` rather than an `#ifdef`.
- **Dependency files go stale.** After moving, renaming or deleting a header run a clean build, or delete the stale `.d` files in `out/`: they reference the old path, and make reports it as "No rule to make target".
- **The link is three-pass.** `pass1.elf` → the module export table; `pass2.elf` (the final link without a symbol table) → `nm` → `symtab_data.cpp`, the table stack traces resolve symbols from → the final ELF, whose own `nm` must give the same table or the link fails. Every function the `ffi` crate declares that the staticlib defines is kept by `-u` (`ffi_keep.rsp`), and the build fails when a module it makes imports what its kernel does not export (`modules.bound`). Touching the link or symbol resolution: `docs/build.md`.
- **The Rust toolchain is a dated nightly and the external crates are vendored.** `src/crates/rust-toolchain.toml` pins it (the Dockerfile and both CI workflows install from there), `src/crates/vendor` holds the sources and the Makefile builds with `cargo --offline`, so no build touches the network. After changing a dependency -- or bumping the pin, which changes what std itself resolves to -- run `scripts/vendor.sh` and commit what it produces.
- **The kernel keeps SSE and the x87 off**, because it saves neither's state on a context switch: the x86 C++ is built with `-mno-sse -mno-80387` (arm64's with `-mgeneral-regs-only`), so its floating point is calls to `compiler_builtins`' soft-float helpers. A crate that dispatches to SSE2/AVX2 at run time cannot be built for such a target, or faults on the first AP that runs it: the RustCrypto crates are forced onto their software backends in `src/crates/.cargo/config.toml` (`sha2` by its `force-soft` feature), and a new dependency of that kind needs the same. `getrandom` has no bare-metal backend; `tls` registers the kernel's entropy pool as its custom one (`docs/tls.md`).

### Gates

**Every refactor step must keep `./scripts/smoke-test.sh` green** (markers `After test` → `Preempt is now on` → `boot: complete`, fail-fast on `PANIC:`; `scripts/smoke-arm64.sh` is the arm64 equivalent, `SMOKE_HVF=1` for HVF; both take `--skip-build`). **Gate on exit codes, never on grepping output.** The x86 smoke boot attaches virtio-blk (modern), virtio-scsi (legacy), NVMe, virtio-net and virtio-rng, so it covers the Rust/MSI-X path too. CI boots a `UBSAN=1 RUSTUB=1` build on both architectures as well (docs/build.md): there, and under any gate run on one, the first undefined operation in the C++, and the first unsafe precondition `core` finds violated in the Rust, is a panic naming its site.

What a smoke boot cannot notice has a test of its own, each there for a failure that looks like success; when you meet another such failure, write another. Run the one that covers what you touched -- **manual** ones are not in CI and are run by hand; "both backends" is AMD-V and VT-x. ### Running and debugging

```sh
./scripts/qemu.sh          # x86-64 ISO boot, 2 CPUs, virtio-net, GDB stub on :1234, serial -> nos.log
./scripts/qemu-disk.sh     # disk boot with virtio-blk/scsi/nvme/net/rng attached
./scripts/run.sh           # Linux/KVM, all host CPUs, isa-debug-exit device
./scripts/qemu-arm64.sh    # arm64 `virt`, the fast dev loop: HVF on Apple Silicon (~4x faster; NOS_TCG=1 forces TCG),
                           # virtio-mmio blk/net/rng, serial -> nos-arm64.log; NOS_UDPSHELL=9000 for the UDP shell on :9000
python3 scripts/udpsh.py 127.0.0.1   # remote shell over UDP (off unless udpshell= is given -- everywhere)
./scripts/gdb64.sh         # GDB; QEMU must be started with -s (bin/kernel64.elf has the symbols)
./scripts/gdb-arm64.sh     # the same for arm64 (qemu-arm64.sh -s), needs gdb-multiarch
```

More in `docs/run.md` and `docs/debug.md`. On a running kernel, `trace on <group>` records a component's events and `trace show`, `trace latency` and `trace dump` read them back (`tracepoints=` turns groups on at boot; `scripts/trace-decode.py` reads a dump on the host; `docs/tracing.md`); `profile` samples where the CPUs spend their time (`docs/profiler.md`).

**Kernel command line**: set via GRUB (`build/grub.cfg`) on x86-64 or QEMU `-append` on arm64, parsed in `kernel/parameters.cpp`, listed in full in `docs/kernel-parameters.md`. To bisect a boot failure: `smp=off` (BSP only), `maxcpus=N` (the BSP included), `loglevel=N`, then take subsystems out of the path with `usb=off` (x86-64: skip xHCI bring-up), `its=off` (arm64: no ITS, MSI degrades gracefully), `hwrng=off`, `rc=off` (skip `/etc/rc`), `dhcp=auto|on|off`, `console=serial` / `console=vga`. On a machine with no serial port `netconsole=ip:port` is the only way to see the log of a boot that dies -- `scripts/netconsole.py` receives it, `nctail=N` keeps the newest N KiB of the pre-link backlog -- and `disklog=on` is for a boot that dies before its network is up.

**Tests run at boot, not via a test runner.** Self-tests live in `src/base/kernel/test.cpp`, each a `stdlib::Error test_xxx()` run from `test::test()` (called in `main.cpp:main2`) or `test::test_multi_tasking()`; `rust_test` runs the Rust side's from the same place. To add one, write a `test_xxx()` and register it in the `test()` dispatcher. **To run a single test, edit `test()` to call only that function**, rebuild, boot, and watch `nos.log`.

## Architecture

Boot flow (x86-64), in full in `docs/boot.md`: `arch/x86_64/boot64.asm` (Multiboot2 entry, 32→64-bit transition, AP trampoline) → `kernel/main.cpp` `main2` (BSP: paging, dmesg, page allocator, runs `test()`) → `bp_startup` (interrupts, IOAPIC, timers, brings up APs via INIT/SIPI, starts SoftIrq/TCP/shell, prints `boot: complete`). APs enter via `ap_main` → `ap_startup`. On arm64 the equivalent path is `arch/arm64/boot.S` → `arch/arm64/main_arm64.cpp`, with PSCI `CPU_ON` for APs.

Source layout (directory by directory in `docs/project-layout.md`):

- **`src/base/` is the fundamentals.** `hal/` — the portable contracts, each header selecting the arch backend at compile time; `arch/x86_64/` and `arch/arm64/` — everything arch-specific, from the boot entry to the PTE encoding; `kernel/` — the scheduler, tasks, interrupt dispatch, SoftIrq, timers, locks, panic and backtrace, dmesg, the shell (`cmd.cpp`), the self-tests (`test.cpp`), the module loader (`module.cpp`) and the Rust bridge (`rust_ffi.cpp`); `mm/` — page tables, the page, pool and VA allocators, `new`/`delete`; `drivers/` — serial, the console, PIT/HPET/RTC, the 8042 keyboard, PCI, MSI-X, ACPI, and **no virtio and no USB**; `lib/` — `stdlib::`, the freestanding stdlib and containers.
- **`src/crates/` is everything on top**, one cargo workspace built into a `#![no_std]` `staticlib` (`libkernel.a`), a directory an area (each crate in `docs/project-layout.md`): `kernel/` (the staticlib's entry points); `base/` (`ffi`, `kcore`, `kmod`, `events`, `random`: what every crate of the image stands on); `layers/` -- **the whole block, filesystem and network layers** (`block`, `fs`: the VFS over ext2, ext4, ramfs and procfs, and `net`), with `tls`, the management bus `mgmt` and the message channel `ipc` -- there is no `src/base/{block,net,fs}` and no C++ view of any of them; `drivers/` by what they drive (`block/`, `net/`, `rng/`, `usb`, and `virtio`, the transport the virtio drivers share); `hypervisor/` (`hvarch` + `hv`, workspace members but **not** default members: compiled only into the `hv` module, so a kernel without it carries no hypervisor; and `hvboot`, a program of the guest's, `/lib/hvboot`); `modules/` -- **loadable modules**, Rust-only, by area, each built on its own into a `.ko` that `insmod` binds against an export table generated from the `ffi` declarations; `common/` -- the crates with **no kernel in them and no `unsafe`**, by area (`crc`, `codec`, `cluster/{raft,registry}`, `ipc/{ipcwire,mgmtwire}`, `net/{netwire,web,ssh}`, `storage/{extfmt,diskimage,nbsmeta,nbscs,nbswire}`, `text/{conf,edit}`), which a module, hvboot and the host's fuzzers link as they are. External crates (rustls, RustCrypto's, dalek's, `sha2`, `zeroize`) are vendored in `src/crates/vendor`. A new crate goes into the area its job is in -- a new area if none fits -- and never at the top: `make check` refuses that, a crate that is not a member, and a `common/` crate that depends on the kernel or allows `unsafe` (`scripts/check-crates.py`).
- **`fuzz/` is the host's half of the gates**: the kernel's own sources compiled for the host -- `hv/`, `net/` and `fs/` (those two over the machine in `common/`: the C++ half stood in for, tasks one at a time, the lock rules), `ipc/`, `raft/`, `nbs/`, and `cpp/`, the C++ under the sanitizers by its own `Makefile` -- and the kernel-free crates' harnesses (`crc/`, `extfmt/`, `hvboot/`, `diskimage/`, `edit/`, `web/`), each run by its `scripts/*-fuzz.py` or `*-test.py`; outside `src/crates/`, whose `.cargo/config.toml` would make any cargo build under it a kernel build.
- **Dependencies run one way**: a driver depends on `block` or `net`, `fs` on `block`, `net` on `fs` and `tls` -- which is below `net`, so it takes its transport as a trait.

## Conventions (critical)

This file is the authoritative copy of the project's rules: `docs/` explains and expands them, and where the two disagree this file wins. They are how the goal at the top is kept in practice. First which language new code is in, then the non-obvious rules -- C++ first, and then what goes for both:

- **New code is Rust unless it has to be C++.** C++ is for the fundamentals that are C++ already, and for extending those in place: boot and arch bring-up, the MMU and the allocators, the scheduler and tasks, the locks, interrupt dispatch, timers, the HAL, the core of the shell, the module loader. Everything that sits on them is Rust: every driver (block, net, USB, virtio, anything on the PCI bus), every network protocol and service, every filesystem, the block layer, and the shell commands that belong to any of those -- a new command goes in the crate that owns the data (`igbdump` is in `drivers/net/igb`), not in `cmd.cpp`. Do not add a C++ view of a Rust layer or grow a C ABI so that new C++ can reach Rust: if new C++ would need one, the code is on the wrong side. When a C++ subsystem has to be reworked substantially anyway, moving it to Rust is the preferred direction. **What is optional is a loadable module** (`src/crates/modules/`, `docs/modules.md`): a server, a load generator, a diagnostic -- anything a machine can boot and run without -- is a `.ko` over `kcore`, as `sshd`, `netblk`, `netload` and `blkload` are. The one thing a module cannot be today is a disk's or a NIC's driver: those register with their layer as trait objects from inside the image, and there is no C name for a module to bind.
- **Write a thing once, where everything that needs it can link it.** Code two places need -- a format, a checksum, a parser, a wire, a data structure -- lives in one crate: under `src/crates/common/<area>/` when it needs no kernel (no kernel and no `unsafe`, so the image, the modules, hvboot and the host's fuzzers link the same copy, and `make check` holds it there), in `kcore` when it wraps a kernel service; in C++, in `lib/` (`stdlib::`). Before writing a helper, look in `common/`, `kcore` and `lib/` for it; when you find a second copy of something, merge the two rather than fix one of them -- the CRCs had six copies before `common/crc`. The one copy kept apart on purpose is a test's judge: a fuzzer's model or checker shares nothing with what it judges (fs-fuzz's ext4 check has a CRC32C of its own).
- **Freestanding constraints**: no `std::` (use `stdlib::` from `lib/stdlib.h`), no exceptions/RTTI, **no lambdas/closures**, no `thread_local`, no heap before `PageAllocatorImpl::setup()`. `volatile` compound assignments are banned — write `x = x + y`.
- **Static constructors do not run, and the link refuses one.** This kernel runs no `.init_array`, so a global whose type has a non-`constexpr` constructor or a non-trivial destructor would be left as zeroes -- `Pci`'s config lock and the arm64 console's sat unregistered with the watchdog that way for as long as they existed -- and both linker scripts now fail such a build ("a static constructor or destructor"). Give the type a `constexpr` constructor and a trivial destructor, every member initialised (as `Atomic` and `RawRwSpinLock` have), or make the object a function-local static: the singleton + explicit init pattern, `static Foo& get_instance(){ static Foo i; return i; }` plus a `bool setup()` called once at boot. Heap-allocate non-trivial objects (e.g. `mm::talloc<T, Tag>()`) rather than using static arrays of them.
- **Error handling**: return `bool`/pointer for pass-fail, `stdlib::Error` (`lib/error.h`, carries code, file, line and function) for rich errors, `stdlib::Result<T>` (`lib/result.h`) for value+error. Build with `make_error(stdlib::Error::NO_MEMORY)` / `make_success()`; a `Result<T>` converts implicitly from a `T` and from an `Error`, so `return 42;` and `return make_error(...);` are both all it takes. Always check return values. On error paths, release every resource acquired so far in reverse order. `BUG_ON(cond)` and `PANIC("fmt", …)` for invariant violations.
- **OOM and `operator new`**: plain `new T(...)` **panics on OOM** and never returns `nullptr` — the compiler assumes the plain form is non-null, so a null check after it is dead code. Fallible allocations must use `new (mm::NO_THROW) T(...)` (the compiler keeps that null check; from `stdlib::` code it is spelled `new (kernel::mm::NO_THROW) T[...]`, as in `lib/vector.h`) or `mm::talloc<T, Tag>()`, and check the result. Why the plain form cannot be made nullable is in `mm/new.h` and `docs/paging.md`.
- **Never allocate or free with a spinlock held.** `mm::free`/`mm::alloc` reach the page allocator, which shoots down the TLB on every other CPU (`CpuTable::invalidate_tlb_range` → IPI → `WaitGroup::wait`) and waits for all of them to answer. A CPU spinning on the lock you hold has interrupts off and can never answer, so the two wait for each other forever -- no panic, nothing to reset the machine. Collect what needs releasing into a local list under the lock, unlock, then release. Better still, do not allocate on a datapath at all: net frames come from the frame pool, built once at boot and recycled through per-CPU caches over a lockless ring, and a driver hands a finished TX frame to `TxQueue::done` -- the only way out of `flush_tx` a frame has -- for the net layer to release off the lock. `CpuTable::send_tlb_ipi` panics after ten seconds naming the CPUs that never answered, so a new instance of this bug is a report rather than a dead machine.
- **Memory refcounting** is explicit and easy to get wrong — `PageTable::map_page(va, page)` does `+1`, `get_page(phy_addr)` does `+1` (caller must `put()`), `unmap_page(va)` is net-0 (a `get` and a `put` inside) and returns the `Page*`. To fully undo a `map_page`: `unmap_page`, then `page->put()`. To free a mapped page: `unmap_page` + `free_page` + `put`. `free_page` alone only puts the page back on the free list; it does not touch the refcount (the table is in `docs/paging.md`).
- **Never map DMA/device memory at `phys_addr + KERNEL_SPACE_BASE` directly.** Always go through `mm::map_pages` / `mm::alloc_map_pages` so the `VaAllocator` tracks the VA. `mm::alloc_map_pages` / `unmap_free_pages` allocate contiguous frames and free them on release; `mm::map_pages` / `unmap_pages` map frames the caller supplies and keeps (`mm/new.h`; the table is in `docs/paging.md`).
- **The kernel image is W^X on both arches.** Late in boot `protect_range` splits it into text RX / rodata RO+NX / data RW+NX (`main.cpp`, `main_arm64.cpp`), and MMIO mappings are NX. Self-modifying code, executing from a heap buffer, or writing through a pointer into `.rodata` faults instead of silently working.
- **Memory barriers**: `Barrier()` is gone. Pick the semantic variant from `hal/barrier.h`: `hal::smp_wmb/smp_rmb` (CPU↔CPU publish/consume, e.g. seqlock), `hal::dma_wmb/dma_rmb` (CPU↔device rings/doorbells/OWN bits), `hal::compiler_barrier` (compiler-only). On x86 they all compile to a compiler barrier; on arm64 they become `dmb` — misclassification is invisible on x86 and bites on arm64. In Rust, device ordering uses `kcore::barrier::dma_wmb/dma_rmb` (`dmb oshst/oshld` on arm64) — `core::sync::atomic::fence` is NOT a substitute: it emits `dmb ish`, whose inner-shareable domain does not order against a PCIe master. Consuming device-written state needs a read barrier *after* the index/phase/OWN check and before the payload reads (an address-independent load pair is not ordered by a control dependency on arm64) — see `virtio::Queue::take_used`, nvme `read_cqe`, r8168 `harvest`.
- **Write Rust with as little `unsafe` as the job allows, and put what is left in `kcore` and at the C ABI, not in the layers.** A new driver, protocol, filesystem or module should need none of its own beyond an `unsafe impl` saying a struct is plain words and the entry point C++ calls it by. Reach for the `kcore` type first (the list is in the next section, the long form in `docs/rust.md`); when the shape you need has none, add the type to `kcore` -- once, with the reason it is sound in its comment -- rather than an `unsafe` block at every use. Do not lower the count by hiding it: a pointer kept as a `usize`, a macro that folds ten blocks into one, a safe wrapper that trusts what it is given, all leave the risk and remove the warning. `scripts/unsafe-count.py [crate...]` counts the sites (blocks, `unsafe fn`, `unsafe impl`); a change that raises a layer's or a driver's number should be able to say why.
- **Arch discipline**: common code includes `hal/*` headers only; an architecture's own headers are for arch code, x86-only drivers and three documented exemptions (`kernel/main.cpp`, `kernel/cmd.cpp`, `kernel/irq_balance.cpp`). `hal::` wrappers: `is_interrupt_enabled`, `irq_save/irq_restore` (not RFLAGS), `get_sp/set_sp/get_fp` (not get_rsp/get_rbp), `read_cycle_counter` (not read_tsc), `irq_eoi/send_ipi/get_current_cpu_hw_id` (not Lapic::), `tlb_flush_page/tlb_flush_all` (not Invlpg/CR3). Per-arch member functions (e.g. `CpuTable::start_all`) live in arch TUs.
- **Naming is Rust's, with Google's data members.** Types -- classes, structs, unions, enums, aliases -- and enumerators are `PascalCase`; namespaces, functions, methods, parameters, locals, globals and statics `snake_case`; constants -- `constexpr`, `const` globals, `static const` members and locals, value template parameters -- `SCREAMING_SNAKE_CASE`; a class's data members `snake_case_` with a trailing underscore, a struct's and a union's without. The macros on every other line -- `klog`, `klog_error`, `make_error`, `make_success`, and `likely`/`unlikely` as Linux names them -- are `snake_case`, and those names are theirs alone: nothing else is called that, as a function-like macro takes every `name(` there is; `BUG_ON`, `PANIC` and `PANIC_CTX`, where the kernel stops, are `SCREAMING_SNAKE_CASE` to be seen, as every other macro is. A struct's field and a global carry no mark, so nothing but a different name keeps a parameter or a local from taking their place: never give one the name of a field of its own struct or of a global it can see -- clang's `-Wshadow` says nothing of a parameter that hides a global, which is how the rename to this convention once made `ubsan::set_warn_only` store into its own argument. Nor give a constant the name of a C library's macro (`PATH_MAX`, `LINE_MAX`, `BLOCK_SIZE`): the fuzzers build the kernel's C++ against the host's headers, where the macro's value would be taken without a word.
- **Style**: namespaces `kernel::`, `kernel::mm::`, `stdlib::`, `hal::`. Log with `klog(level, "fmt", …)` / Rust `klog!(...)` -- a line into dmesg, the consoles, netconsole and the disk log; level 0 is always visible and the per-subsystem level constants (`KBD_LL`, `USB_LL`, `PAGE_ALLOCATOR_LL`, …) are at the top of `kernel/klog.h`. To debug a subsystem raise one there, or raise the global level with the `loglevel N` shell command or the `loglevel=N` boot parameter -- no rebuild, which is what you want on a box whose only console is a UDP socket. A format string is C's printf, and the compiler holds every call to it (`PRINTF_FORMAT`, `-Wformat=2 -Werror`): a `ulong` is `%lu` or `%lX`, a `u32` `%u`, an address as a pointer `%p`, a `u64` cast to `ulong` (it is `unsigned long long` on a Mac, where the fuzzers build it). A new printf-like function gets `PRINTF_FORMAT`, and a format is a literal at its call -- never a variable, never handed on through a template (a `Task` takes a name, not a format). No magic numbers: name constants (`static const`, `constexpr` or an `enum`, in the header or class they belong to). `/* ... */` for a multi-line comment, `//` for a one-line one; `auto` is fine for a deduced local, and the smart pointers in `lib/` are there to be used. Preserve existing formatting; don't reflow unchanged code. 4-space indent.
- **Debug and profile with tracepoints.** What a component did, in what order, and where its time went is read off a trace window, not guessed at or told by log lines on a hot path: the log is for lines a person reads, a tracepoint for events too many and too fast for that -- a few dozen nanoseconds to record, a byte's load and a branch when off. A component with a path worth measuring -- a request through its hand-offs, a queue, a wait, a protocol's decisions -- gets its events as it is written, as the scheduler, the hypervisor, a guest's disk and TCP have: in C++ an event is its `tp::Id`, payload, fields and `EVENTS` line in `kernel/tracepoint.{h,cpp}`, and one Rust records has its line in `base/kcore/src/trace/events.rs` too, emitted with `kcore::trace::on::<E>()` and `emit(&E)` (`docs/tracing.md`, "An event of its own"). Measure a new site's cost when off on the hot path it sits on (`trace bench`, interleaved boots of the build before and after) rather than assume it.
- **C++ gets a second pass for undefined behaviour before it is done.** Once it is written and builds, re-read the diff looking for nothing else: `-Wall -Wextra -Werror` and cppcheck catch little of it, and in a kernel UB is not a crash at the faulty line but a machine that wedges somewhere else, on one architecture, at one optimisation level. What to look for, most of it from bugs this tree has had: a value from outside -- a device register, a packet, a disk, the Rust side, the shell -- used as an index, a length, a shift count or a handle before it is range-checked (`1 << n` with `n` from hardware, `count * size` that can wrap, a PCI slot shifted into an address unmasked); signed overflow and conversions that truncate; a read of anything not yet initialised, padding copied out and members a constructor skips included; a `reinterpret_cast` onto bytes that may be misaligned or are another type's (wire and on-disk structures go through `mem_cpy` or byte accessors); a pointer or reference that outlives what it points at -- a stack object handed to a callback, a list entry freed while still linked, an object freed while an interrupt handler or another CPU may still hold it; shared state touched from two CPUs or from an interrupt without the lock, the atomic or the barrier that orders it, and `volatile` standing in for any of those; a null check after plain `new`, or none after a fallible allocation; a static object with a constructor; control falling off the end of a non-void function. Say in the change what was checked and what was found. Then run the gate for the code on a `UBSAN=1` build (docs/build.md): it catches at run time what the read missed on the paths the gate drives -- and nothing on the paths it does not, so it does not replace the read.
- The C++ build uses `-Wall -Wextra -Wformat=2 -Werror`, so warnings break the build.

## Rust: `ffi`, `kcore`, the layers, the drivers

`docs/rust.md` is the long form of this section -- the reason behind each rule, a map of what `kcore` has, how a driver is written -- and `docs/modules.md` is the same for a module. Read it before writing Rust here. What must not be missed:

- **A kernel service reaches Rust in three steps**: the C++ function in `src/base/kernel/rust_ffi.cpp` (all of the bridge's C++ lives in that one file), its raw declaration in `src/crates/base/ffi/src/<module>.rs`, the safe wrapper in `src/crates/base/kcore/src/<module>.rs`. A module gets it by the same three: its export table is generated from the `ffi` declarations, and a change to them changes the digest every `.ko` carries, so modules are rebuilt with the kernel.
- **`base/ffi/` is declarations only**: raw pointers, no references, a kernel object an opaque `usize` handle, 0 for failure. The blocks are `unsafe extern "C" {` **at the start of a line** -- the Makefile's export table looks for exactly that. `pub safe fn` is for a function that is sound for *any* argument at *any* time, and only after reading its definition: values-only C++ that validates them, or a Rust export that only looks its handle up in a table. Not for anything with a buffer, a callback or a C++ handle; not for the PCI config reads (the arm64 ECAM accessor does not bound the slot or the function); not for `irq_restore` or `preempt_enable`, which can open a window inside somebody else's critical section.
- **`base/kcore/` is where a handle becomes a type**: `Drop` calls the matching `kernel_*_destroy` / `kernel_*_stop` / `kernel_*_put`, a handle that must not be `Send`/`Sync` carries `PhantomData<*const ()>`, and ownership crosses to C++ inside the wrapper, so no call site has a `forget` to remember. Its `block`, `net`, `tcp` and `fs` modules are those layers *as a loadable module reaches them*; inside the image the crates call each other as crates (`block::Disk`, `net::Nic`, `net::Frame`, `fs::vfs::Open`).
- **The C ABI is for what is on the other side of a link** -- C++, or a module. Between two pieces of Rust in the image the seam is a trait or a `&mut dyn` (`vfs::FileSystem`, `http::Sink`, `UdpHandler`, `tls::Transport`, `BlockDriver`, `NetDriver`), not an `extern "C" fn(ctx: *mut u8, …)` table. An export that trusts a pointer is `unsafe extern "C" fn` with a `# Safety` section, and **an export nobody calls is deleted**, not kept for symmetry. A C++ file that needs a Rust layer declares the `rust_*` / `kernel_*` calls it makes where it makes them. What a layer and a module both need, and that needs no kernel, is a crate under `common/` (`netwire`, `ssh`, `crc`): a module is linked on its own and cannot link a layer, so anything else would be written twice. **A small function on a datapath that another crate calls is `#[inline]`** -- there is no LTO, so without it an accessor is a call with bounds checks of its own, in the image and twice over in a module (`docs/rust.md` has the numbers).
- **Before an `unsafe` block, look for the type that makes it unnecessary** (the reason each is sound is in the type's own comment):
  - data under a lock: `Mutex<T>`, `SpinLock<T>`, `IrqSpinLock<T>`, `PreemptSpinLock<T>`, `TryLock<T>` -- a lock owns what it guards, never a bare lock beside an `UnsafeCell`
  - the one of something: a `Once`/`OnceBox` static; per-CPU state: `PerCpu<LocalCounter…>` or `CpuLocal<T>`, never an array indexed by `cpu::id()`
  - what only the receive path touches: an `RxOwned<T>`, reached with the `&mut RxContext` a `UdpHandler` is lent
  - an on-disk or on-wire structure: `kcore::pod`
  - a handle from outside -- a net device, a TCP connection, a block device, an open file: **looked up in its table, not dereferenced**, so a bad one is `None` rather than undefined behaviour
  - a graph: an arena and ids (`fs::vnode::Tree`), not raw pointers
  - a callback -- interrupt, timer, soft IRQ, task: a function item over its `&'static` target (`MsixInterrupt::register_for(&table, 0, dev, Dev::interrupt)`), with no `ctx` to cast and no closure that captures
  - device memory: a descriptor ring is a `&'static [D]` of `Volatile` cells (`DmaBuffer::leak_ring`), and anything else in a `DmaBuffer` crosses through `load`/`store`/`bytes`
  - what waits when dropped -- a `UdpListener`, a `TaskHandle`, an interrupt handle: in its own `Lock<Option<..>>`: `take()` it under the lock, drop it after. Dropped under the lock its wait needs, it is a deadlock
  - a tracepoint: `kcore::trace::on::<E>()` and `emit(&E)`, the payload declared with its event in `base/kcore/src/trace/events.rs` and described in `kernel/tracepoint.cpp`'s table, which every boot holds it to
- **A driver** implements `block::BlockDriver`, `net::NetDriver` or `random::Source` over a device that is `Box::leak`ed and so `&'static`; shutdown is `quiesce(&self)`, not a `Drop`, and nothing is freed. An interrupt handler runs in IRQ context and may run on two CPUs at once: registers, atomics and IRQ-safe locks, no sleeping, no allocating. A NIC's rings are its `NetDriver::Tx`/`Rx`: `net::register` takes them over -- last, because from there on the driver is called -- and lends them as `&mut` to `flush_tx` and `process_rx`, so nothing else can reach them; a finished TX frame goes to `TxQueue::done`, never dropped there (the spinlock rule). The smallest real example of each kind: `drivers/block/virtio_blk` (`drivers/block/nvme` for the asynchronous path), `drivers/net/r8168`, `drivers/rng/virtio_rng`.
