# Features

Everything the kernel does today, by subsystem. For where the code lives see
[Project layout](project-layout.md); for the interactive shell see
[Shell commands](shell-commands.md).

- **virtio in Rust** — the split virtqueue, the transport contract and both buses (virtio-pci modern *and* legacy, virtio-mmio v2) are `src/rust/virtio`; **virtio-rng** and **virtio-blk** are the devices on it (`src/rust/drivers/`), the second of them being where the root filesystem lives. The remaining virtio devices (net, scsi) still stand on the C++ foundation and move over one at a time
- **Two architectures** — x86-64 (Multiboot2/GRUB, ISO or MBR disk boot, **legacy BIOS and UEFI firmware**) and arm64 (QEMU `virt` board, Linux `Image` boot protocol); portable code goes through a HAL layer (`src/cpp/hal/`), arch backends live in `src/cpp/arch/`
- **SMP** — up to 64 CPUs (20 exercised on real hardware); AP bootstrap via INIT/SIPI on x86-64, PSCI `CPU_ON` on arm64, APs started one at a time, `maxcpus=N` to cap them
- **Preemptive multitasking** — per-CPU task queues, round-robin scheduling, load-balanced task placement
- **Virtual memory** — 4-level paging (4 KB pages), high-half kernel at `0xFFFF800001000000`, TLB shootdown across CPUs via IPI
- **Page allocator** — fixed-size block allocator (1–128 contiguous pages), pool allocator (32 B – 2 KB), `new`/`delete` support
- **ACPI** — RSDP/RSDT/MADT parsing for LAPIC/IOAPIC discovery and IRQ→GSI routing
- **Interrupts** — IDT with exception handlers, IOAPIC routing (edge + level-triggered), LAPIC IPI, PIC (remapped then disabled), round-robin IRQ balancing across CPUs once SMP is up (IOAPIC lines only over the apic ids a physical-mode redirection entry can name, MSI-X over all of them)
- **arm64 port** — GICv3 interrupt controller with ITS (PCIe MSI delivered as LPIs, `its=on` by default), EL1 exception vectors, ARM generic timer (per-CPU), PL011 UART, FDT (device tree) parsing, PCIe ECAM, virtio-mmio transport, broadcast TLBI, semantic memory barriers (`dmb`) throughout; NVMe over ITS-delivered MSI works end-to-end
- **Drivers** — serial (COM1), screen console (EGA text on BIOS, 8x16 font on the bootloader's pixel framebuffer under UEFI), PIT (10 ms tick, SeqLock-protected counters), RTC (CMOS wall clock), PS/2 keyboard (8042), **USB HID keyboard over xHCI** (BIOS/UEFI handoff, root-port and hub enumeration, boot-protocol reports), PCI bus scan, LAPIC, IOAPIC, **virtio-net**, **virtio-scsi** (legacy + modern virtio-pci transport), **virtio-blk** and **virtio-rng** (Rust, on the Rust virtio foundation), **NVMe** (Rust, MSI-X interrupt-driven), **Realtek RTL8168/RTL8125** and **Intel 82576/I210** (igb) NICs (Rust)
- **Block I/O** — asynchronous, interrupt-driven block request queue with DMA slot pool, `BlockRequest` submission with `WaitGroup` completion, direct DMA from caller buffers (page-aligned), virtqueue locking (`RawSpinLock`) for safe interrupt/task concurrency, early-boot polling fallback, SoftIrq-based retry for ring-full conditions, **the block layer in Rust** (`src/rust/block`): the device table a driver registers an ops table with — from C++ or from Rust alike — the claims that keep a mount, the disk log and a writer off each other's sectors, and the partition tables (MBR and GPT) each partition is registered from
- **Networking** — virtio-net driver with asynchronous interrupt-driven TX/RX, software frame queues (256-entry TX/RX) in `NetDevice` base class, reference-counted `NetFrame` descriptors for zero-copy DMA, TX slot pool with bitmask allocation, SoftIrq-based TX retry and RX processing, IP routing (subnet mask + gateway from DHCP, off-subnet traffic forwarded to gateway), ARP (cache, request, reply, dump), IPv4/UDP transmit, ICMP echo (ping reply + send, per-type statistics), DHCP client with lease renewal (sets IP, subnet mask, gateway, DNS server), DNS resolver with 32-entry cache (A-record queries, name compression, DHCP-provided server), **TCP** (connection state machine, 3-way handshake, sequence/ack tracking, retransmission timers, MSS negotiation, send/receive ring buffers, graceful close with FIN exchange, RST handling, ephemeral port allocation, granular locking: `Mutex` for ports, `RawSpinLock` for pool and per-connection state, SoftIrq-driven timer processing), **HTTP client** (URL parsing, DNS resolution, TCP connection, request/response, chunked transfer decoding, redirect following for 301/302/303/307/308 with loop limit including http→https, URLs up to 2 KiB (a GitHub release download redirects to a ~900-character signed link) that are refused rather than truncated when longer, a streaming body sink so a 20 MB download costs one 16 KiB buffer instead of 20 MB of heap, an idle receive timeout, `wget` shell command), **[HTTPS](tls.md)** (TLS 1.3/1.2 through rustls in `no_std` with the RustCrypto provider, certificate chains verified against the compiled-in Mozilla root store and the RTC, entropy from the kernel's [ChaCha20 pool](random.md), the socket staying on the C++ side), [UDP remote shell](udp-shell.md) (execute kernel commands over the network), network device abstraction with per-protocol packet counters, `MacAddress`/`IpAddress` structs (IPv6-ready tagged union)
- **Filesystem** — VFS with mount points, path resolution and a file API (open/read/write/seek, append, truncate, rename, stat, readdir; open files pin their vnode), one filesystem call at a time; **ext2 read-write** (rev 1, 1–4 KiB blocks, direct/indirect/doubly-indirect blocks, sparse files, lazy directory loading, e2fsck-clean write ordering, `valid` state kept like Linux; refuses ext3/ext4 features, mounts `gdt_csum` images read-only); a **root filesystem on disk** chosen by `root=auto|<dev>|LABEL=|UUID=`, made with `scripts/mkrootfs.sh` / `scripts/build-disk.sh` (no root privileges), and a self-test (`fstest`) run at boot by the smoke tests; ramfs (in-memory), nanofs (the kernel's own checksummed 64 MiB filesystem, copy-on-write, files up to 1 MiB), procfs
- **[Randomness](random.md)** — a ChaCha20 CSPRNG (`Kernel::Random`: fast key erasure for output, absorb for seeding, RFC 8439 block function checked at boot against the RFC's vector) seeded from every entropy source the machine has: the CPU's own instruction behind a HAL seam (RDSEED/RDRAND on x86-64, RNDR/RNDRRS on arm64, with a self-test that refuses an instruction answering the same value every time), virtio-rng, and a timing-jitter collector with von Neumann debiasing as the last resort on a machine with neither. `EntropySource`/`EntropySourceTable` is the registry the pool reseeds from; `random` and `entropy` shell commands, `hwrng=off` to exercise the fallback
- **Power management** — ACPI S5 shutdown, keyboard controller reset/reboot
- **Interactive shell** — trace output suppressed during shell session (dmesg only), restored on shutdown; commands: `ps`, `top`, `profile`, `stacks`, `netload`, `cpu`, `lscpu`, `bt <pid>`, `dmesg [lines] [filter]`, `loglevel [N]`, `uptime`, `date`, `memusage`, `meminfo`, `memcheck`, `pci`, `disks`, `diskread`, `diskwrite`, `irqstat`, `net`, `arp`, `netpool`, `icmpstat`, `tcpstat`, `udpsend`, `ping`, `nslookup`, `dnsflush`, `dhcp`, `wget`, `random`, `entropy`, `format`, `mount`, `umount`, `ls`, `cat`, `cp`, `write`, `append`, `mkdir`, `touch`, `rm`, `mv`, `stat`, `sync`, `fstest`, `crc32`, `sha256`, `grubenv`, `panic`, `version`, `cls`, `help`, `poweroff`, `reboot` — see [Shell commands](shell-commands.md)
- **Timekeeping** — TSC calibration via PIT channel 2 (multi-round median), KVM paravirt clock (`kvmclock`) for accurate VM time, RTC wall clock, layered clock source selection (kvmclock → calibrated TSC → PIT fallback), `GetBootTime()` / `GetWallTimeSecs()` API
- **All of the machine's RAM, up to 512 GiB** — the bootstrap linear map
  covers the first 4 GiB at 2 MiB granularity, then one 1 GiB block per GiB
  of RAM above it (x86-64: needs CPUID PDPE1GB, which everything since
  Nehalem/Barcelona has; arm64: an L1 block, always available at a 4 KiB
  granule). 512 GiB is where one PDPT/L1 table runs out. Blocks with no
  usable RAM in them are left unmapped. Where the hardware cannot do it the
  kernel falls back to 4 GiB and says so; `meminfo` and two `mm:` lines at
  boot always report RAM reported vs. RAM reachable, so the difference is
  never silent. The page-descriptor array that comes with all that RAM (one
  32-byte `Page` per 4 KiB frame, so 512 MiB on a 64 GiB box) gets a
  contiguous carve-out of its own and is mapped with 2 MiB pages, since every
  free-list walk touches it at random. Cost: building the free list still
  touches every page twice, about 0.6 µs in total each, so a 64 GiB machine
  spends around ten seconds of its boot there.
- **Per-CPU tick** — each CPU runs its own periodic timer (x86-64: the local
  APIC timer, calibrated once against the established clock; arm64: the
  generic timer), rather than one HPET interrupt on one CPU fanned out to
  every other by IPI. That removes a write to the interrupt command register
  per CPU per tick, and removes the single point of failure: a CPU that stops
  answering interrupts now stops only its own tick, while the others keep
  ticking and the watchdog notices it. The HPET stays as the timekeeper.
- **Kernel infrastructure** — spinlocks, mutexes, SeqLock (single-writer/multi-reader), atomics, wait groups, SoftIrq deferred processing, IPI tasks, timers, watchdog, stack traces with symbol resolution, dmesg ring buffer (512 KB, 2048 messages, recycled lines counted and reported), panic handler with backtrace and CPU/task context, per-device interrupt statistics, AP startup diagnostics, virtual-to-physical address translation (4-level page table walk), byte-order helpers (`Htons`/`Htonl`/`Ntohs`/`Ntohl`)
- **Optimized stdlib** — `MemSet`, `MemCpy`, `MemCmp`, `StrLen`, `StrCmp`, `StrStr` implemented in x86-64 assembly using `rep stosq`/`rep movsq`/`repe cmpsb`/`repne scasb` (portable C versions on arm64)
- **Rust support** — `#![no_std]` Rust crates linked into the kernel via `staticlib`, FFI bridge (`rust_ffi.cpp`) exposing kernel services to Rust: spinlocks, mutexes, wait groups, timers, SoftIRQ, MSI-X interrupts, legacy interrupts, DMA allocation, MMIO mapping, PCI config space, block device and network device registration, CPU/IPI/task APIs. **kcore** library provides safe Rust wrappers around kernel primitives. **NVMe driver** written entirely in Rust — PCI BAR mapping, admin + I/O queue pairs, MSI-X interrupt-driven completion, WaitGroup-based synchronous I/O, multi-device support, proper RAII cleanup on shutdown
- **[Loadable kernel modules](modules.md)** — kernel services written in Rust, each a crate built into a position-independent ELF `.ko` and loaded into the running kernel with `insmod` (listed with `lsmod`, removed with `rmmod`), on both architectures. The loader maps each segment into pages of its own, binds the module's imports by name against an export table generated from the `ffi` crate's declarations, applies its dynamic relocations, gives every segment the permissions its program header asks for (never writable and executable at once), and refuses a module built against another kernel interface. A module can add shell commands; `insmod` and `rmmod` each run in a task of their own, so an unload waiting out a module command still running holds up neither the shell nor `lsmod`. Images up to 16 MiB. Backtraces — the panic report, `bt`, the profiler — name a module's functions, from a demangled table the build puts in the `.ko`. `blkload`, a module in the tree, load-tests a disk or a partition from the shell: IOPS, bandwidth, latency percentiles. Tagged releases carry every module, built for both architectures, for `wget` from a running kernel. The boot self-test loads, exercises and unloads a module embedded in the kernel image
- **[netblk](netblk.md)** — a module that serves an NVMe disk, or a partition of one, as a block device over UDP, zero-copy both ways: the disk DMAs a read straight into the frame the NIC transmits, and a write straight out of the frame the NIC received, which then goes back as the reply. Requests pass from the receive softirq to a pinned worker and back from the disk's interrupt through the kernel's lockless rings; the worker rings the disk's doorbell and the NIC's once a batch, polls while completions are due and blocks on an event otherwise. It stands on a UDP listener that is handed the frame itself, batched transmit, virtio-net receiving into pool frames, and an asynchronous block path (`BlockDevice::SubmitAsync`) the NVMe driver implements. `scripts/netblk.py` is its client, `scripts/netblk-test.py` its end-to-end test on both architectures
- **[sshd](sshd.md)** — an SSH server in a module: an OpenSSH client logs in with an Ed25519 key and gets the kernel's shell, with a line editor and history on a terminal, or runs one command (`ssh host dmesg`). curve25519-sha256 with OpenSSH's strict key exchange, ssh-ed25519 host and user keys, chacha20-poly1305@openssh.com, client-started rekeying followed even mid-output, flow control both ways; the protocol lives in a crate of its own (`src/rust/ssh`) over the vendored RustCrypto and dalek crates, the module supplies TCP, the files and the shell. The host key is made on the first start and kept in OpenSSH's own format, the authorized keys in an OpenSSH `authorized_keys`; 8 connections, at most 4 of them logging in, a 30-second login grace, keepalives. `/etc/rc` -- shell commands the shell runs once at boot, edited with `rc` -- loads and starts it on a machine whose only console is the network. It was the first user of the TCP stack's passive side, which gained an `Accept` that times out and notices its listener closed, and resets for connections a closed listener never accepted
- **Boot tests** — allocator, btree, ring buffer, stack trace, multitasking, contiguous page alloc (up to 128 pages), parsing helpers, block device table, memset, memcpy, memcmp, strlen, strcmp, strstr
